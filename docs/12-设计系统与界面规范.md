# 12 · 设计系统与界面规范

2026-09-18 建立。适用于 `src/template.html`、`src/tokens.css`、`src/app/ui/*.js`，以及安卓 / iOS 壳里和外观相关的代码。

> **这是一个以手机为主的 app。** 安卓 WebView 壳是主要形态，iOS 壳在开发中，Web 版和它们是同一个页面，只作辅助。所有界面都先按 390px 宽的手机设计和验收；600 / 900 / 1280px 三个断点只在更宽的屏幕上逐级展开。
>
> 可视化的设计系统页面（令牌色板、组件预览、品牌书）：<https://claude.ai/artifact/AnZvVZEak5xQW2uPqGuZMp>。它是给人看的参考；规则以**本文件**和 **`src/tokens.css`** 为准，两边冲突时改 Artifact。

## 1. 基本原则

1. **让数字可信。** 这是测算工具，不是营销页面。数字从哪里来（来源档次）、按什么口径算、哪里还不确定，都要摆在数字旁边。
2. **清晰是默认风格。** 其它风格只换令牌，不换结构：同一套组件、同一套间距，只有颜色、描边、圆角、字体、效果不同。
3. **只用令牌。** 颜色、阴影、圆角只允许在 `src/tokens.css` 里写值，其它地方一律写 `var(--令牌)`。`tools/test-design-tokens.mjs` 守住这条，是发版必跑的第 8 组。
4. **手机上看过才算做完。** 改完界面必须在 390px 宽度下截图确认；可能的话，再装到真机或模拟器上看一遍。

## 2. 令牌与主题

### 2.1 令牌文件

- `src/tokens.css` 是唯一来源。构建时 `tools/build.mjs` 把它注入 `src/template.html` 的 `/*__TOKENS__*/`，占位符必须独占一行。
- CSS 写 `var(--x)`；JS 的内联样式同样写 `'var(--x)'` 字符串。
- 不认 CSS 变量的地方，要在**绘制时**用 `ui/theme.js` 的 `tokenColor('--x')` 取实际值，包括腾讯地图 / 天地图的样式对象、data: URI、canvas、导出快照。所以切换主题后，这些地方要重绘。
- 算法层 `src/app/algo/*` 不得引用任何令牌工具，也不得出现 `var(--`（纯度守卫）。

### 2.2 三套主题

| `data-theme` | 名称 | 明暗 | 说明 |
|---|---|---|---|
| `clear` | 清晰（默认） | 浅 | `:root` 的取值，源码原有外观 |
| `clear-dark` | 清晰·深色 | 深 | 中性深灰，保持清晰风格的克制；刻意不偏藏蓝，和科技风格区分开 |
| `tech` | 科技·调度大屏 | 固定深色 | 藏蓝底、青色信号光、等宽数字、网格底纹、1px 描边、小圆角、关键数字微光 |

- **两个开关：** 「风格」（清晰 / 科技）和「明暗」（跟随系统 / 浅色 / 深色）。选科技时明暗固定为深色，「明暗」开关禁用。
- **入口与存储：** 入口在页头「帮助」左边的「外观」按钮。设置存在 localStorage 的 `iproute.v2.ui`，格式为 `{style:'clear'|'tech', mode:'system'|'light'|'dark'}`。
- **首屏：** `<head>` 里的内联脚本在样式生效前算好 `data-theme`，避免首屏闪白；读不到存储时回退默认值。
- **新增主题：** 在 `src/tokens.css` 里加一个 `[data-theme="…"]` 覆盖块，**每个颜色令牌都要给值**，然后过对比度守卫。组件样式不改。

### 2.3 令牌分组

各令牌的取值和用途注释都在 `src/tokens.css` 里，这里只说明分组，避免文档和取值两处维护。

| 分组 | 代表令牌 | 用途 |
|---|---|---|
| 文字 | `ink` `ink2` `ink3` | 正文 / 次级 / 提示与单位 |
| 面 | `bg` `card` `gray-bg` `field-bg` | 页面底、卡片、卡内填充块、输入框底 |
| 线 | `line` `line2` `field-border` `ghost-border` | 卡片外框、卡内分隔、输入框边框、幽灵按钮边框 |
| 品牌 | `blue` `blue-bg` `blue-ink` `on-fill` | 主色、选中底、价格数字、实色填充上的字 |
| 语义对 | `teal` `amber` `red` `coral` `gray`，各带 `-bg` | 通过 / 提醒 / 越限 / 预留 / 中性 |
| 浮层 | `header-glass` `nav-glass` `scrim` `tooltip-bg` `tooltip-ink` | 毛玻璃、遮罩、提示气泡 |
| 系统栏 | `system-bar` | 页头色的不透明版，必须写成 `#RRGGBB`；供 `<meta name="theme-color">` 和安卓壳同步状态栏 / 导航栏 |
| 图表 | `chart-*`（11 个） | 价格组成，顺序和颜色固定 |
| 地图 | `map-*`、`map-region-1…8` | 网架图线路、节点、标签、区域着色 |
| 区域网络 | `region-*` | 只用在「区域共用网络」卡片 |
| 形状 | `r` `radius-*` `hairline` `emphasis` | 圆角级数、发丝线、强调描边 |
| 字体 | `font-sans` `font-mono` `font-num` | 正文、公式、数字（科技风格换成等宽） |
| 效果 | `num-glow` `page-pattern` `card-highlight` `hero-field-glow` `focus-ring*` `shadow-*` | 清晰风格下都是 none，或只用于浮层和焦点 |
| 层级 / 布局 | `z-*` `app-width-*` `col-*` | 叠放顺序、内容列宽 |

**新增令牌的流程：** 先起一个语义名（说明用途，不写颜色，例如写 `field-bg`，不写 `white-2`），在三套主题里都给值，再过守卫。合并后同步设计系统 Artifact。

## 3. 颜色

- 页面是冷灰的 `bg`，上面放 `card`。分层靠发丝线（`hairline` 宽的 `line`，卡片内部用 `line2`），**卡片不加阴影**。
- **只有一个品牌色 `blue`**，用于主按钮、选中、焦点、当前导航、选中路线。**价格主数字和路线名用 `blue-ink`。**
- 语义色都是「浅底 + 同色深字」一对，深色主题里反过来是「深底 + 亮字」，但仍然成对使用：`teal` 表示通过、已核定、终点；`amber` 表示提醒、口径改动、区域口径；`red` 表示越限、错误、缺数。**颜色不能单独表达状态，旁边一定要有字。**
- 卡片内部的块用 `gray-bg`，卡片里不要再嵌白卡。
- `region-*` 只用在区域共用网络上；`chart-*` 的顺序固定（见 `ui/calc.js` 的 `COMP_ITEMS`）。

## 4. 字体与数字

- 正文用系统字体栈 `font-sans`（苹方 / 系统无衬线），不加载网络字体，离线包和 APK 里都能直接用。公式用 `font-mono`。
- **数字位置一律挂 `font-num` 并使用 `tabular-nums`**，让列里的数字对齐、变化时不左右跳。科技风格把 `font-num` 换成等宽字体，靠的就是这个钩子。
- 字号按手机取值，允许的字号集合写在守卫的 `FONT_SIZES` 里。**要新增字号，先进设计系统，再改守卫**，不要为了让守卫变绿直接加值。CSS 字号最小 10.5px；拓扑图 SVG 的 `font-size` 属性另有 9 / 10 / 10.5 三档，那是 viewBox 单位、随图缩放，不是屏幕像素。
- 字重有含义：400 正文，500 标签和幽灵按钮，600 标题，700 数字（方案价 750，分项金额 650）。
- 输入框字号是 13–15px。iOS 上小于 16px 会触发聚焦放大，页面靠 viewport 的 `maximum-scale=1` 阻止，安卓壳固定 `setTextZoom(100)`。这两处不要删。

## 5. 间距、布局与安全区

- 手机页面左右边距 16px，卡片内边距 14px，卡片之间 12px，卡片内的网格间距 8px。600px 起边距 20px，900px 起 24px。组件内部还有 5 / 7 / 9 / 11px 的源码原值，保持不动，**不要为了凑网格去取整**。
- 手机上内容列最宽 480px，居中；底部导航也在这个宽度内。
- 测算页从上到下依次是：主卡（选省、报价、结果、口径摘要、价格组成）→ 可选路线 → 方案详情 → 交易连接 → 折叠的明细卡。宽屏分两栏或三栏，手机上纵向堆叠。
- 安全区：底部导航和弹层底栏用 `max(…, env(safe-area-inset-bottom))`；页脚为导航留出约 64px。状态栏交给壳处理（见第 12 节）。

## 6. 边框、圆角、阴影

- 边框默认 `hairline` 宽（清晰风格 0.5px，科技风格 1px）。强调描边用 `emphasis`：选中的路线卡、主报价输入框、区域网架虚线框。
- 圆角由外向内逐级变小：弹层 `radius-sheet` → 卡片 `r` → 按钮 `radius-btn` → 输入框 `radius-field` → 行内元素 `radius-inline` → 档次标 `radius-tag`。标签用 `radius-pill`（清晰风格为胶囊，科技风格为小方角）。
- 阴影只给浮在页面上方的东西：弹层、确认框、导览卡、错误提示，以及焦点环。

## 7. 状态与交互

- **选中：** `blue` 描边、`blue-bg` 底、`blue-ink` 字。路线卡、分段按钮、推荐卡都用这一套。
- **聚焦：** 描边变 `blue`，再叠加 `focus-ring` 外晕（主报价框用 `focus-ring-hero`，超限输入用 `focus-ring-bad`）。
- **不参与计算：** 字段加 `.off`，置灰但留在原位，不要隐藏。
- **忙碌：** `disabled`，不透明度 .55，光标 `wait`，文字改成进行时（「正在分析…」）。**按下：** 不透明度 .85。
- **手机上没有悬停。** 靠悬停显示的信息必须也能通过聚焦看到（元素加 `tabindex="0"`），例如价格条的提示气泡。
- **可点区域不小于 44px。** 外观小的控件（弹层关闭按钮、密钥显隐按钮、页头小按钮、复选框标签）用透明伪元素把点击区扩大，伪元素要垫在控件内容下面，别挡住控件本身。唯一例外是费率库筛选按钮组 `.seg.wrap`：行距只有 5px，扩大后会抢相邻一行的点击。
- 弹层和面板（参数弹层、外观面板）都能用 Esc 和安卓返回键关闭。
- 复选框和单选框保留原生外观（`appearance:auto`），用 `accent-color:var(--blue)` 着色，勾选状态必须看得见。
- 动效只有三处：弹层滑出和遮罩淡入 .25s，路线卡选中过渡 .15s，价格条聚焦 .12s。不要新增装饰性动画。

## 8. 可访问性底线（每套主题都要满足，守卫会检查）

- 文字对它所在的底色 ≥ 4.5:1：`ink`、`ink2`、`ink3` 在 `card`、`bg`、`gray-bg` 上，各语义色在各自的 `-bg` 上，`on-fill` 在 `blue` 和 `amber` 上，提示气泡文字在气泡底上。
- 非文字 ≥ 3:1：输入框边框对输入框底，焦点描边对输入框底。
- **已知例外（保持原值）：** 清晰浅色的网架图非路线省名 `map-label`（2.7:1）。它属于弱化的背景信息，另外两套主题都已达标。
- 状态不能只靠颜色区分；红和绿不能只靠色相区分，旁边都要有字。

## 9. 内容与语气

- **中文、克制、可核对。** 写事实和后果，不写形容词。可以写「候选集已达枚举上限（800 条），排序仅基于已枚举部分，不能保证全局最优」，不要写「为您找到最佳方案！」。
- **不把没核实的说成确定的。** 写「参考参数未越限 · ATC待核实」，不写「可行」。
- **缺数就说缺数。** 缺失值显示「—」，没有采集到的写「未获取」「待补」「待核实」，并说明后果。任何时候都不要把缺失显示成 0（用 `format.js` 的 `fmt` / `num`）。
- **来源档次只有四个固定说法：** 发改委核定、国网披露、区域/送出省口径、待补（用 `format.js` 的 `TIER` / `tierTag`）。
- **数字与单位：** 界面上单位是跟在数字后的小一号 `ink3` 字；写在句子里时数字和单位之间空一格（「输电价 51.1 元/MWh」）。金额保留 1–2 位小数，路线卡上取整，千分位按 zh-CN 格式。
- **标点与符号：** 全角中文标点；引用界面上的词或专有名词用「」，文号用〔〕；「·」分隔元信息，两侧各空一格；「→」表示送受方向，「↔」表示区域网架的接入与交付。
- **标签与按钮：** 字段标签写成「名词 + 单位」或「名词 · 限定」，不加冒号。按钮写 2–6 个字的动词短语，需要数量就写进按钮。
- **符号而不是 emoji：** ⚠ 放在提醒句开头，✓ / ✗ 用于状态行，★ 标记最优路线的切换点，＋ / － 表示折叠的开合。不用 emoji。
- **免责声明原文照用，放在每页页脚：** 「本工具为测算与比选辅助，不构成交易建议；实际可交易路径以电力交易中心公布为准。」

## 10. 图标与品牌标记

- 线性 SVG 内联：圆头圆角描边、不填充；导航图标 20px、描边 1.5，按钮里的图标 15–18px。当前导航项的图标描边切到 `blue`，按钮里的图标跟随按钮文字色（`currentColor`）。
- 没有图标字体，也没有 emoji 图标。
- 唯一的品牌标记是应用图标：`blue` 方底上的白色输电塔和导线（`android/app/src/main/res`）。没有文字标，产品名直接用系统字体写。

## 11. 地图与合规

- 底图只用白名单里的腾讯地图和天地图；**应用不画行政区划边界**，省界只由底图提供（详见 CLAUDE.md「底图与合规」）。
- 深色主题下，腾讯地图 / 天地图的**底图本身仍是浅色**：底图配色要在地图平台侧配置个性化样式，代码里改不了。线路、节点、叠加层都跟随令牌，内置拓扑图完全跟随主题。
- **已知限制：** 深色主题下，在线底图上的路线名和站名是浅色字压在浅色底图上，对比度偏低。要改需要单独给「在线底图模式」配一组令牌，还没有做。

## 12. 平台壳

- **安卓：** `res/values/themes.xml`（浅）、`res/values-v27/themes.xml`（导航栏图标深浅从 API 27 才可设）和 `res/values-night/themes.xml`（深）让 WebView 的 `prefers-color-scheme` 跟随系统，同时设好状态栏和导航栏颜色；WebView 背景设为透明，窗口底色用 `page_bg`。在 app 内切换风格时，页面调用 `IPRouteShell.setSystemBars(hex, lightIcons)` 同步系统栏（`lightIcons=true` 表示深底配浅色图标，只接受 `#RRGGBB`）。这个桥只能改颜色（页面里可能加载第三方地图脚本），**不要往里加任何别的能力**。API 26 的浅色模式下，导航栏保持系统默认深色，因为那一代改不了导航栏图标深浅，设成白底会看不见按钮。
- **iOS：** WKWebView 自动跟随系统明暗。同名桥接还没做，见 `ios/ROADMAP.md`。
- Web：`<meta name="theme-color">` 由 `ui/theme.js` 按当前主题的 `system-bar` 改写。
- 主题接口都在 `ui/theme.js`：`applyTheme`、`resolveTheme`、`watchSystemTheme`（只在「跟随系统」时响应系统变化）、`syncSystemBars`、`openAppearance` / `closeAppearance`。存储键常量是 `config.js` 的 `LS_UI`；`<head>` 内联脚本里写的是同名字面串，改名要两处同步。

## 13. 改界面的标准流程（人和 agent 都适用）

1. **开分支：** 在 `.claude/worktrees/<分支名把 / 换成 ->` 开 worktree，不在 `main` 上改。
2. **先查设计系统：** 找现成的组件、类名和令牌。确实需要新的颜色、字号或圆角，先按第 2.3 节新增令牌（三套主题都给值），不要在组件里写死。
3. **改代码：** 改 `src/template.html`、`src/app/ui/*.js`，只写 `var(--x)`；JS 取实际颜色用 `tokenColor()`。
4. **构建和守卫：** 跑 `node tools/build.mjs`，再跑 `node tools/test-design-tokens.mjs`。
5. **截图对比：**
   ```bash
   node tools/ui-shots.mjs .runtime/ui-shots/before --theme clear   # 改动前先截（三套主题各一次）
   node tools/ui-shots.mjs .runtime/ui-shots/after  --theme clear   # 改动后再截
   node tools/ui-shots.mjs --compare .runtime/ui-shots/before .runtime/ui-shots/after
   ```
   - **纯重构**（令牌化、改名、搬规则）必须零像素差异。
   - **有意的视觉改动**，差异只能出现在预期的画面里，并逐张目视检查三套主题。
6. **看真机：** 至少看一眼 390px 截图；涉及交互、滚动、安全区、键盘时，打包 APK（`node android/build-apk.mjs`）或在 iOS 模拟器里走一遍。
7. **跑测试：** 发版必跑的 8 组 + e2e 全绿。
8. **提交：** 用中文 conventional commits；PR 描述里附 390px 的改前改后截图（有主题差异时附三套）。
9. **同步设计系统：** 合并后同步设计系统 Artifact。在 Claude Code 里说「按最新代码重新同步设计系统」即可，它会合并改动、保留说明文字。
