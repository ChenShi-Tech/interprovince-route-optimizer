> 面向接手本项目的人（含未来的 AI 会话）。这里记录的是**不看代码就会踩坑**的东西。
> 最后更新：2026-09-15。

---

## 一、项目是什么

省间电力现货交易的**路径优选测算工具**。给定送端省与受端省，枚举跨省输电通道的所有可行组合，按三种口径比选并给出费用拆解。

- Web 版：`index.html`，**自包含单文件**，离线可用，已发布到 `https://interprovince-route.app.workbuddy.host/`
- 安卓端：`android/` WebView 壳工程，`node android/build-apk.mjs` 出 APK
- iOS 端：`ios/`，**截至 2026-09-15 只有目录与路线图文档，Xcode 工程尚未创建**
- 数据层：`data/fixed-prices.json`（价格） + `src/extra.json`（非价格），构建后产出 `shared/app-data.json` 供两端共用

## 二、四条纪律（最高优先级）

### 1. 不得编造费率数值

找不到就写 `null` 并在文档里记录已检索路径。这条高于一切——一个编造的费率比一个缺失的费率危害大得多。

**同样适用于容量**：ATC（可用输电能力）我国不公开，宁可标「未获取」也不编系数。

### 2. 价格数据只有一处来源

`data/fixed-prices.json`。改价格**只改这个文件**，然后 `node tools/build.mjs`。

`docs/tariff.json` 是采集档案（含原文摘录），不参与构建。`shared/`、`index.html` 都是构建产物，**不要手改**——下次构建会被覆盖。

### 3. 费率必须分档标注来源

字段 `tier`：`gov`（发改委核定，有文号）/ `grid`（国网披露，含报备价）/ `region`（区域电网或送出省口径）。

**不得把报备价与核定价混为一谈。** 路径含非 `gov` 段时界面要主动告警。

### 4. 改动算法后必须跑基线

```
node tools/baseline-check.mjs      # 必须 1739/1739 通过
```

改了费率或通道数据则先 `node tools/baseline2.mjs` 重新生成基线。

## 三、日常开发流程

```
改代码 → node tools/release.mjs "提交信息"
```

`release.mjs` 依次做：**构建 → 5 组测试 → 提交 → 推送**，任一测试不过就中止，不会提交半成品。

5 组测试：

| 测试 | 内容 |
|---|---|
| `test-modules.mjs` | 模块结构 + 算法层纯度（不引用界面全局） |
| `test-data-share.mjs` | Web 与安卓端数据一致性 |
| `baseline-check.mjs` | **算法回归基线 1739 条路线** |
| `test-prefill.mjs` | 受端参数预填行为 |
| `test-interaction.mjs` | 交互与计价口径回归 |

## 五、算法层为什么是纯函数

`src/app/algo/*` **不引用任何界面全局**。数据经 `data` 参数、用户参数经 `input` 传入：

```js
solve(input, data)                                 // 唯一入口
regionFee(env, fromCode, toCode)                   // 显式接收行进方向
enumPaths(adj, src, dst, maxHops, cap, weightOf)   // 展开顺序由调用方给权重函数
```

**这是为了手机端能原样复用同一份算法**，不必从 HTML 里抠代码。`tools/test-modules.mjs` 会守住这条——它会检测算法层是否出现裸引用界面全局，并已用反向注入验证过守卫本身有效。

## 六、六个容易踩的坑

### ① 网损是乘法项，不能当边权

多段串联时送达系数 `D = Π(1−ηᵢ)`。必须两步：先用线性近似求候选路径，再用乘性公式精确重算排序。

### ② 路径标识必须用节点序列

用 `nodes.join('>')`，**不能用边对象的 `from`/`to`**——对向通行的边，其存储方向与行进方向相反，用边拼键会把 A→B→C 与 C→B→A 误判为同一条。

**同类错误还会出现在任何用到边方向的地方。** 例如区域电网费：曾因读存储方向而非行进方向，在「湖北→山西」（长南荆存为山西→湖北）上错收华中 25.6 而非华北 10.8，**导致 1739 条路线里 1504 条数值出错**。凡是需要判断方向的逻辑，一律传实际行进的起止节点。

### ③ 输出目录不能用 `dist/`

发布工具会把 `dist/` 当作构建产物排除，站点上会 404。本项目用 `shared/`。

### ④ 构建占位符必须独占一行

`src/template.html` 里 `/*__DATA__*/` 和 `/*__APP__*/` 前后不能有残留文字——替换后会变成悬空代码导致语法错误。

### ⑤ 842 号附件的单位是「元/千千瓦时」

数值上**等于 元/兆瓦时**，不要误按「分/千瓦时」再乘 10。

### ⑥ 部署是叠加式的

重新发布**不会删除**站点上已移除的文件。仓库清理后线上可能仍有残留（无害，但要知道原因）。

## 七、推送机制（为什么不用 git push）

本机所有流量走本地代理（`127.0.0.1:60205`），该代理放行 `api.github.com`，但对 `github.com` 返回 502。**`git push` / `git pull` / `git ls-remote` 都不可用**，`gh` CLI 正常。

因此推送走 GitHub Git Data API，脚本在 `tools/push-github.mjs`。

**它用 `base_tree` 在远端现有树上叠加本地文件**，而不是用本地文件重建整棵树——后者会在多会话并行时删掉别人推送的内容（2026-09-14 真实发生过，误删 18 个文件）。

两条使用注意：

- **改文件名 = 新增 + 遗留旧文件。** `base_tree` 会保留远端旧名文件形成重复。确认新旧文件 blob sha 相同后，用 `--allow-delete` 清理。
- 推送前会列出「远端有、本地没有」的文件，默认保留；确实要删须显式加 `--allow-delete`。

另：`git ls-files` 默认对中文路径做八进制转义，脚本读文件会 ENOENT，**必须用 `git -c core.quotepath=false ls-files`**。
