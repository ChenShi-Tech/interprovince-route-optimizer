# 数据接口说明

> 面向 Web 与安卓端共用的数据契约。两端使用**同一次构建产出的同一份数据**，保证数值与结构完全一致。

---

## 一、产物与消费方式

| 产物 | 消费方 | 说明 |
|---|---|---|
| `index.html` | Web | 自包含单文件，数据内联，离线可用 |
| `shared/app-data.json` | 安卓端 / 其它消费方 | 独立 JSON，缩进格式，便于阅读与调试 |
| `shared/app-data.min.json` | 安卓端 | 同内容的紧凑版，体积约少 25% |
| `data/fixed-prices.json` | **唯一数据源** | 改价格只改这里，然后重新构建 |

三者由 `node tools/build.mjs` 一次产出，**不要手工修改 `shared/` 与 `index.html`**——它们是构建产物。

安卓端有三种取数方式，实测均可用：

| 通道 | 地址 / 方式 | 适用 |
|---|---|---|
| ① 随包内置 | 把 `shared/app-data.min.json` 放进 RN 工程 assets，启动时读取 | **离线优先，推荐作为兜底** |
| ② 站点同目录 | `https://interprovince-route.app.workbuddy.host/shared/app-data.json` | 已随 Web 版一起部署，返回 `application/json` |
| ③ CDN 拉取 | `https://cdn.jsdelivr.net/gh/ChenShi-Tech/interprovince-route-optimizer@main/shared/app-data.json` | 国内可达，返回 `application/json`；仓库更新后自动生效 |

> 另有 GitHub raw（`raw.githubusercontent.com`）也可取到，但国内访问不稳定，不建议作为主通道。

推荐做法是**两者结合**：内置一份作兜底，联网时用 ② 或 ③ 比对 `priceVersion`，不一致再刷新。

> ⚠️ 输出目录**不要用 `dist/`**：发布工具会把它当作构建产物排除，导致站点上 404。本项目的输出目录因此取名为 `shared/`。同目录下的 `README.md`、`data/`、`docs/` 均已验证可正常访问。

> 💡 若将来接入 WorkBuddy 云服务（数据库 / 登录 / 存储），本文件的字段结构可直接作为 `tariffs` 表的设计基础：`tier`、`doc`、`eff`、`excerpt` 已具备版本与溯源的语义，补充 `valid_from` / `valid_to` / `verified_by` 即可满足审计要求。

## 二、版本与完整性

```json
{
  "schema": "iproute-app-data/v5",
  "builtAt": "2026-09-17T12:00:00.000Z",
  "priceVersion": "<随 data/fixed-prices.json 变化>",
  "dataHash": "<随载荷变化>",
  "counts": { "stations": 98, "channels": 91, "channelsPriced": 86,
              "sections": 10, "provinces": 31, "nonInterprovincial": 3 }
}
```

| 字段 | 用途 |
|---|---|
| `schema` | 结构版本。字段增减时递增，消费方据此做兼容判断 |
| `priceVersion` | **价格数据指纹**，由 `data/fixed-prices.json` 的内容哈希得出。只要价格变了这个值就变 |
| `dataHash` | 载荷指纹，用于校验传输完整性 |
| `counts` | 快速自检：条数与预期不符说明数据不完整 |

Web 端把 `priceVersion` 渲染在「费率库 → 数据管理」中，两端可直接肉眼比对。

**版本不一致时不要混用两端数据**——同一笔交易在两个端算出的落地价会因为费率版本不同而不一致，这比算出错误结果更难排查。

## 三、数据结构

### `ST` 站点（换流站 / 变电站）

```ts
type Station = {
  n: string;    // 名称，如「锦屏换流站」
  a: string;    // 精确站址，如「四川凉山州西昌市裕隆乡」
  lng: number;  // 经度（县/市级近似，原文可到乡镇/村级）
  lat: number;
  p: string;    // 所属省代码
};
```

用途：地图打点、路径落点展示。**98 个站点已覆盖主要换流站，非全部。**

### `NIC` 非省间通道台账（v5 新增）

```ts
type NonInterprovincial = {
  _说明: string; _依据: string[];
  条目: Array<{ 名称, 送端, 受端, 类型, 电压等级, 容量MW, 投运日期,
                输电价: number|null, 线损率: number|null,
                不建边原因: string, 来源: string, 备注?: string }>;
};
```

物理上存在、但在「省级行政区」图模型里无法建成跨省边的工程：广东省内分区背靠背（大湾区广州、东莞）
与对俄跨境受入（黑河背靠背）。**只登记、不参与枚举与计价**，供界面「通道资料」展示。
`counts.nonInterprovincial` 为其条数。

### `CH` 通道（跨省输电通道）—— 核心

```ts
type Channel = {
  id: string;
  n: string;          // 通道名
  fn: string;         // 别名，多个用 / 分隔
  from: string;       // 送端省代码
  to: string;         // 受端省代码
  stFrom: string|null; // 送端换流站 id（指向 ST）
  stTo: string|null;   // 受端换流站 id
  kv: string;         // 电压等级，如 ±800kV
  type: 'DC'|'AC';
  loss: number;       // 线损率 %
  t: number|null;     // 输电价 元/MWh（容量制工程为折算的等效度电成本）
  tRaw: number|null;  // 发改委核定原值；容量制工程为 null
  sendFee: number;    // 仅作为路径首段时使用的送端省内段费用（送出省输电价格）元/MWh
  cap: number|null;   // 用于容量校验的容量，优先取实际输送能力
  capRated: number|null;   // 额定容量
  capActual: number|null;  // 实际输送能力
  capBasis: 'cap'|'rated'|'unknown';  // cap 的取值口径
  capSrc: string;     // 容量来源说明
  priceType: 'energy'|'capacity';     // 计价方式
  capPrice: object|null;              // 容量制工程的容量电价与文号
  capEq: number|null;                 // 容量制折算的等效度电成本
  tier: 'gov'|'grid'|'region';        // 数据可信度
  doc: string;        // 核定文号
  eff: string;        // 生效日期
  bill: string;       // 计费口径
  tax: boolean; incLoss: boolean;
  sendFee: number;
  excerpt: string;    // 原文摘录
  hist: Array<{ effective_from, tariff_raw, loss_rate_pct, doc_number, note }>;
  tradable: boolean;  // 资料分类标记，不能证明当期可交易（抽象交流接口、价格待核通道为 false）
  pricePending?: boolean; // v4：价格待核。南网云广/普侨/高肇/兴安/禄高肇 5 条物理直流无独立核定输电价格
                          //     （收费并入 842 号「云南送广东/贵州送广东」等聚合交易成分），
                          //     建边但**一律不参与路径枚举**，否则会按 0 元过网费产出价格虚低的错误方案。
                          //     消费方必须与主算法同样处理，不能把它们当免费通道。
  bidir: boolean;     // v2：能否双向通行。单向送电直流 false；德宝、青藏、长南荆、辛洹、灵宝、高岭、云霄与全部联络线 true
  regional: boolean;  // v2：是否属区域共用网络（仅联络线 true）；过境非买方区域时按该区域计电量电价
  tRev: number|null;  // v2：联络线反向行进时的送出省参考价（仅路径首段归入 send）；专项工程 null（核定价与方向无关）
  sendFeeRev: number|null; // v3：双向专项工程反向行进时的送端省内段费用（对侧省的送出省输电价格）；其余 null
  dirNote: string;    // v3：方向依据（公开报道 / 文件编号）
  marginalNote: string;    // v3：容量制工程边际输电价的说明（辛洹 0、云霄输电权下限）
  status: string; note: string; sourceIssue: string|null;
};
```

`schema` 由 v1 升到 v2 增加了 `bidir` / `regional` / `tRev`，v3 增加了 `sendFeeRev` / `dirNote` / `marginalNote` 与 `PV` 的三个线损字段，其余字段不变。

### `PV` 省级参数

```ts
type Province = {
  n: string; lng: number; lat: number;
  clear: number|null;   // 报价演示值 元/MWh（非实时市场数据）
  net: number|null;     // 受端省网输配电价 元/MWh（220kV 及以上两部制）
  fund: number|null;    // 政府性基金及附加 元/MWh。**可能为 null**
  netSrc: string;       // 取值依据与文号
  inLoss: number|null;      // v3：省内上网环节线损率 %（1077号附件1 注3），受端用户承担，进完整落地价
  exportLoss: number|null;  // v3：送省外上网环节线损率 %（注4），卖方承担，只进口径三
  exportKind: string|null;  // v3：送出省价格口径：「核定外送」或「临时互济条款」
};
```

⚠️ **`fund` 为 `null` 表示该省官方未列出分项标准（当前仅西藏）。消费方必须按「缺失」处理并提示用户，不要静默当作 0** —— 那会低估落地成本。

### 其余

- `SEC` 断面：`{ id, n, edges[], limit, note, src }`
- `RG` 区域电网输电价格（电量电价，元/千瓦时）：`{ 华北, 华东, 华中, 东北, 西北 }`
- `RGOF` 省→区域归属，联络线段按到达省所在区域取区域电网电量电价

---

RLOSS 为区域网损来源/历史与当前值；VALIDITY 为本次价库适用期；PV.effectiveFrom 与 scopeNote 为省级日期和主体范围。

## 四、算法约定（不在数据文件内，需消费方实现）

数据文件只提供数据，**路径规划算法需自行实现**。约定如下，与 Web 版保持一致：

### 中长期节点交付与报价契约

默认中长期测算（marketMode=mlt），交付点为受端省间交易节点（includeDstCost=false）。现货仅预留入口，非 mlt 请求返回尚未实现。

```
D = 工程计费通过率 × 所选区域环节通过率（各区域一次）
E = 选择省内网损另计时：1/D × ρ送/(1-ρ送)，否则 0
A = 1 + lossBearer × (1/D-1) + E
F = 未含的起点送出费 × 首段入口系数
  + Σ 独立工程价 × 工程出口系数 + Σ 适用区域价 × 区域出口系数
border = pGen × A + F
maxSourceQuote = (pDst-F)/A
landed = includeDstCost ? border/(1-ρ受)+pNet+fund : border
```

- pGen 为手填合同/拟报价；pDst 为可选的受端节点目标交付价（界面已不提供，缺省时 senderNet=null、不产出 byC）。PV.clear 只是演示参考。
- sourceQuote=plant：报价未含送出省费；originLossMode=separate 或 included 决定省内网损是否另计。**界面默认 separate（2026-09-17 起）**：1077号附件1 注4 送出价「含税、不含线损」、线损率单列，长三角跨省中长期实施细则（2026）第三十六条规定落地侧价格含「送出省外送输电价格（含送出省外送输电网损）」。算法层缺省（未传该字段）仍按 included，基线在 included/exclude 口径下生成。sourceQuote=export：报价已含送出省费和省内网损，均不再追加。
- regionChargeMode=network（默认）：根据区域共用接口按区域去重，归集至最后出口；buyer：按交易公告在此基础上另计受端区域一次。该收费范围是待确认假设，不代表已取得合同证据。
- regionLossMode=exclude/historical/custom，regionLossRates={华东:1.59,...}。**界面默认 historical（2026-09-17 起）**：同一第三十六条规定落地侧价格含华东跨省输电网损；不计入会让经区域网架的绕行路线显得更便宜（如四川→江苏曾排出 6 段绕行低于锦苏直流）。算法层缺省仍为 exclude。RLOSS.currentPct=null 为当前未核实；historicalPct 为第三周期公开表参考值。内部 verified 模式仅允许使用有证据的 currentPct，当前未提供界面入口。未填不是已核定 0。
- 每段出口电量系数为下游所有计费环节通过率乘积的倒数，含区域网损；本段自身损耗不放大该段输电费。
- 共用交流接口不作专项收费，不逐接口计损；独立专项工程/背靠背直流保留自身口径，incLoss=true 不重复计损。送出省费仅起点一次。
- qty 为节点交付量。到户扩展 consumerQty=qty×(1-ρ受)，amountQty=consumerQty；否则 amountQty=qty。yuan.total/amountQty=landed，不能把到户价直接乘节点电量。
- senderNet 为 maxSourceQuote 的兼容别名，语义已改为“可接受送端报价”，不再是利润/现货卖方结算价。排序 C 取其最大值。
- regionItems 含收费位置、费率、网损率、来源、状态及电量；regionScenarios 提供同一路径未计/历史两情景。pricingIssues 与 priceComplete=false 保留适用性待核状态。
- 受端到户可选输入（缺省与旧口径一致）：dstInLossPct（所选受端电网主体的注3 线损率，电价已含线损的主体如深圳传 0）、dstBilling（single/twopart，仅用于缺项提示）、dstCapFee（两部制容/需量电费按用户负荷率折算的元/到户MWh：月单价×12÷(8.76×负荷率)）、dstSysOpFee（系统运行费手填，null=缺项）。输配电价仍由 pNet 传入，界面按「电网主体 × 电压档 × 单一制/两部制」从数据 VT 带入。
- 送端电站专属送出价可选输入：srcSendFee、srcExportLossPct、srcSendNote（1077号附件1 川、滇、冀北表注4 对特定电站/电量范围另定的送出价与线损口径，须确认额度）。
- 数据新增 VT（`受端分电压输配电价`：30 省 33 个电网主体、156 档，电量/需量/容量电价与注3 线损率）与 SRCX（`送端电站专属送出价`），均在 data/fixed-prices.json；`node tools/audit-voltage-tariffs.mjs .` 用 pdftotext 逐值回对 S11 原件（需 pdftotext，不在发版必跑列表）。线损率与基金不随电压等级变化（注3 每表一个值；基金按用户类别取工商业口径）。
- Dphys、inMW 来自独立物理估算链（含交流估损），不能解释为运行潮流或 ATC。capacityStatus 仅 exceeded/unconfirmed。tradeDate 校验当前价格适用日（界面不再提供交付日期，取当天）；不提供完整历史价库。

来源和可复算数字见 [全模型审计](./09-算法模型与收费标准审计.md)。

### 路径枚举范围（测算约定，不代替交易机构路径）

1. **不重复经过同一交易节点** → 只枚举简单路径
2. **优先选择输电价格最低的交易路径** → 按成本劣化阈值收敛（Web 版默认 10%）
3. 交易节点为**省级电网**（1 省 1 节点），不是变电站
4. **通道方向逐条由 `bidir` 给定**：单向送电直流只按核定方向（1490号附件4第二条「送受端相对明确、潮流方向相对固定」）；德宝、青藏、长南荆、辛洹、灵宝、高岭、云霄经公开报道证实双向运行（`dirNote`），联络线双向
5. **必经通道组件**（可选，Web 版为 `input.mustHave`）：用户指定的通道 id 数组，路径须**全部包含**其中每一条。它作用在枚举与绕行度筛选**之后**，只收窄结果，不参与任何计价或排序；同一条通道不论正向还是反向经过都算命中，方向仍由 `bidir` 决定。id 取自 `CH[].id`，**旧存档里已不存在的 id 要忽略，而不是把结果筛成空**。

Web 端的「通道组件」选择器即这条约束的界面：候选清单取自已通过绕行度筛选的**完整候选集**（不是最终结果），因此选中一个组件后其余组件仍可点选、可取消，用户不会被自己的选择困住。

### 容量校验

```
段 i 入口功率 = 交付电量 / 时段长度 × 物理估算段前系数_i
参考未越限：段入口功率 ≤ CH[i].cap × (1-occPct/100)；unknown/estimate 不可用于实际ATC认证
```

## 五、数值回归

`docs/regression-baseline-v2.json` 记录了 331 个省对、693 条路线的完整数值结果，可作为手机端算法的回归基准：**实现完成后，同一输入应产出同一输出。**

Web 版用 `node tools/baseline-check.mjs` 校验。手机端可将同一组用例写成单测对照。

区域电量电价不含线损（1077号附件2注1）。本期适用的区域网损率尚未核实，当前金额未计区域网损费用，不能解释为该项为零。
返回值 `regionLossMissing: string[]` 列出已计区域电量电价但未计区域网损的区域；结果页和导出报告必须提示该缺项。
