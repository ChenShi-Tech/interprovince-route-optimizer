## 二、两条路线的关系（不是二选一，是先后）

| | 路线 A · WebView 壳 | 路线 B · RN 原生重写 |
|---|---|---|
| 现有进度 | **已完成**，只差打包 | 仅有技术选型建议 |
| 出 APK 所需 | 配工具链 + 跑一个脚本 | 数周开发 |
| 优势 | 极快；与 Web 版永远一致；地图直接复用 | 原生手势与性能；离线更彻底；可用 SQLite |
| 劣势 | 地图仍依赖 WebView 内嵌；数据更新需重新打包 | 工作量大；算法要重写且必须做数值回归 |
| 适用 | **快速让交易员用起来，验证需求** | 需求验证后，做长期主力端 |

**建议：先 A 后 B，不要跳过 A。**
A 的成本几乎为零（工程已存在），能立刻把工具交到交易员手上；而 B 的第一步——**把算法抽成独立 TS 包并用 1739 条基线做回归**——与 A 完全不冲突，可以并行推进，且它是 B 最可验证、最有价值的部分。

## 三、阶段一：WebView 壳出 APK（目标：今天可交付）

### 3.1 配置便携工具链

不需要管理员权限，全部解压到 `~/android-toolchain/`：

| 组件 | 版本 | 用途 |
|---|---|---|
| Temurin JDK | 17 | Gradle 与 Android 构建 |
| Gradle | 8.7 | 构建系统 |
| Android cmdline-tools | latest | 提供 sdkmanager |

所需 SDK 包：`platform-tools`、`platforms;android-34`、`build-tools;34.0.0`

许可文件：`sdk/licenses/android-sdk-license` 需写入 `24333f8a63b6825ea9c5514f83c2829b004d1fee`

### 3.2 打包

```bash
node android/build-apk.mjs
```

流程：重新构建 `index.html` → 拷入 WebView assets → `gradle assembleDebug`。
产物：`android/app/build/outputs/apk/debug/app-debug.apk`，同时复制一份便于分发的命名副本。

### 3.3 真机验收要点

- APK 为 debug 签名，可直接侧载（需允许「安装未知应用」）
- **离线可用**：开飞行模式下启动，路径测算与费率库应完全正常（数据已内联）
- **地图降级**：外部环境下腾讯地图代理不可用，应自动落到内置拓扑图，不得出现空白
- **费率版本**：费率库 → 数据管理里显示的 `priceVersion` 应与 Web 版一致

## 四、阶段二：算法抽包（与阶段一并行，B 路线的前置）

这是整个手机端最值得先做的一步，因为它**有明确的验收标准**。

### 4.1 交付物

一个零依赖的纯 TypeScript 包 `packages/route-engine`，导出：

```ts
enumPaths(adj, src, dst, maxHops, cap)   // 枚举全部简单路径
evalPath(path, ctx)                       // 乘性网损精算
solve(input, data)                        // 三口径比选
```

### 4.2 必须遵守的算法约定

与 Web 版逐条一致（详见 `docs/03-数据接口说明.md` 第四节）：

1. 网损是**乘法项**，不能作最短路边权；两步法：线性近似求候选 → 乘性公式精确重算
2. 路径唯一标识用**节点序列**（`nodes.join('>')`），不能用边的 from/to——对向通行的边存储方向与行进方向相反
3. 段前系数 `1 / Π_{j≥i}(1 − η_j/100)`：越靠送端的段承担越多电量与损耗
4. 落地价含四项省内/通道费用 + 网损折价 + 基金附加，**送出省输电价格不可漏**
5. 容量制工程用折算的等效度电成本参与比选，不可按 0 计

### 4.3 验收标准（硬性）

新引擎必须与 `docs/regression-baseline-v2.json` **逐条吻合**：

- 503 个省对、1739 条路线
- 路径节点序列、落地成本、过网费、送端净收益、送达系数，全部在 1e-4 容差内

**跑不过就不算完成。** 这一条把「移植是否走样」变成了可自动判断的问题。

## 五、阶段三：RN 工程（需求验证后再启动）

技术选型已定（`docs/01-安卓开发框架.md`）：React Native + Expo + TypeScript + Zustand + expo-sqlite。

数据取数三条通道均已实测可用：
1. 随包内置 `shared/app-data.min.json`（离线兜底）
2. 站点同目录 `…/shared/app-data.json`
3. jsDelivr CDN（国内可达）

版本比对用 `priceVersion`。**两端费率版本不一致会导致同一笔交易算出两个落地价，比算出错值更难排查**，因此必须校验。

## 六、风险与边界

| 风险 | 应对 |
|---|---|
| 费率版本两端不一致 | `priceVersion` 强校验，不一致时明确提示而非静默计算 |
| 地图在外部环境失效 | 内置拓扑图兜底（已实现并有测试覆盖） |
| 算法移植走样 | 1739 条回归基线把关 |
| 容量数据不完整 | 8 条通道无实测能力值，界面标注「按额定校验、结果偏乐观」 |
| 西藏基金缺失 | 已显式告警，按 0 计会低估落地成本 |

---

## 七、明确不做

- 一期不做服务端：数据在 git 里、版本可追溯、无需账号体系
- 不做小程序：交易员场景要的是可侧载的 APK 与离线可用
- 不在手机端做价格预测：属另一专业领域，接现有服务
