# iOS 开发路线图 · 总纲

> 编制：2026-09-15。基于本仓库真实状态与本机实测结果，不含推测。
> 分阶段详表见 [`roadmap/`](./roadmap/)，每阶段一份，含目标、技术点与技能、交付物、验收标准、风险。

---

## 一、一句话路线

**先用 WKWebView 壳在两周内把工具送上交易员的手机，再用 SwiftUI 原生重写主力端——算法抽成零依赖的 Swift Package，对着 688 条基线跑回归，不做服务端。**

---

## 二、两把尺子

整条路线只有一个真正的风险：**iOS 上算出来的数和 Web 上不一样**。这个风险不用靠"仔细点"来管，靠两把尺子管：

| 尺子 | 内容 | 判定 |
|---|---|---|
| **算法回归基线** | `docs/regression-baseline-v2.json`：295 个省对、688 条路线 | 路径节点序列、落地成本、过网费、送端净收益、送达系数，全部在 `1e-4` 容差内 |
| **费率版本指纹** | `shared/app-data.json` 的 `priceVersion` 与 `dataHash` | 两端不一致时**明确提示，绝不静默计算** |

两端费率版本不一致会导致同一笔交易算出两个落地价——**这比算出错值更难排查**，因为它看起来是对的。

## 三、阶段总览

| 阶段 | 主题 | 核心目标 | 关键技术点 | 主要交付物 | 验收标准（硬） |
|---|---|---|---|---|---|
| **0** | 环境与基线 | 让「能不能编译、能不能出包、能不能装上真机」在今天就都有答案，并把可回退的基线钉住 | Xcode 工具链管理、签名三件套、Bundle ID 规划、Apple Developer 账号体系 | 空白 SwiftUI 工程（真机可跑）+ 工具链留档 + 账号类型决议 | 真机冷启动成功，`xcodebuild` / SDK 版本输出留档 |
| **1** | Swift 与界面基础 | 打通「参数输入 → 计算 → 方案列表 → 方案详情」这条主链；把前端心智映射到 SwiftUI | Swift 值语义 / `Codable` / async-await / Swift 6 严格并发；SwiftUI 状态与导航；Swift Testing | 费率库浏览器 + 拓扑图小程序 + `RouteEngine` 骨架 | `swift test` 全绿；30 节点 / 70 通道滚动无卡顿 |
| **2** | 最小可用测算 | **iOS 上算出与 Web 版一模一样的落地价**——这是整个 iOS 端唯一不可让步的目标 | 乘法网损两步法、节点序列标识、段前系数、四项费用口径、`Decimal` 精度策略、并发卸载 | iOS 测算 App（三口径比选 + 分段成本拆解） | **688 条基线全部在 `1e-4` 内通过。跑不过就不算完成。** |
| **3** | 费率库与地图 | 费率可编辑、版本可追溯、网架可看——这是本工具区别于一张 Excel 的地方 | SwiftData 持久化、schema 校验与版本留痕、导入导出、`tier` 分档徽标、WKWebView 内嵌合规底图与降级 | 费率编辑页 + 版本对比页 + 地图页（含离线降级） | 改一条费率重算结果同步变化；导入错数据被拦住并指出原因；飞行模式地图不空白 |
| **4** | 工程化与内部分发 | 让交易员装得上、用得着、能升级 | `xcodebuild archive` + `-exportArchive`、Ad Hoc / TestFlight / 企业证书的选择、OTA 安装、隐私清单 | `.ipa` + 分发渠道 + 安装说明 + 升级提示 | 非开发者身份的同事按说明 5 分钟内装上并打开成功 |
| **5** | 原生化与长期演进 | 从「能装」到「好用」 | Widget、App Intents、Share Extension、Face ID、CloudKit / 自建同步的引入时机 | 原生能力至少落地两项 + 跨端回归报告 | 两端同输入同输出；Widget 冷启动 < 1 s |

**周期量级**：阶段 0 为 1–3 天；阶段 1 为 1–2 周；阶段 2 为 2–3 周；阶段 3 为 2–3 周；阶段 4 为 1–2 周；阶段 5 按需启动。阶段 1 与阶段 2 可与安卓侧工作并行。

## 四、需要拍板的四个决策点

### D1 · Apple Developer 账号类型

| | 个人（Individual） | 组织（Organization） |
|---|---|---|
| 年费 | $99 | $99 |
| 门槛 | 无 | 需 **D-U-N-S 编码**，企业官网可访问，企业域名邮箱 |
| 审核周期 | 数天 | **1–4 周** |
| 证书归属 | 绑定个人 Apple ID | 绑定组织 |

**建议走组织**，主体用西安宸识科技有限公司。理由：证书与设备列表绑在个人 Apple ID 上，一旦人员变动就是断链；后续内部分发、上架备案都以公司主体填报。

⚠️ **这是整条路线里唯一的外部等待项，建议与阶段 0 同步启动。**

### D2 · 是否上架 App Store

这条决策同时牵动三件事，必须一起看：

| 若上架 | 若仅内部分发（Ad Hoc / TestFlight 内部） |
|---|---|
| 需完成 **App 备案**（工信部信管〔2023〕105 号），填报 Bundle ID、公钥+MD5、域名 | 不触发备案 |
| 触发 **审核指南 4.2 Minimum Functionality**——WebView 壳会被判为"重新打包的网站"而拒 | 不触发审核 |
| 需 `PrivacyInfo.xcprivacy` 隐私清单（触碰 required-reason API 即必须有，缺失上传直接失败） | Privacy 清单仍建议做，但不是阻塞项 |

**建议：一期只做内部分发。** 详见 [`docs/05-分发与合规.md`](./docs/05-分发与合规.md)。

### D3 · 技术路线 A / B / C

见 [`docs/01-技术选型与路线决策.md`](./docs/01-技术选型与路线决策.md)。结论：**A 先行，B 为主力，C 备选。**

### D4 · 是否升级 macOS 至 26.6

Xcode 27 要求 macOS Tahoe 26.6+，本机当前 26.4。**不升级不影响开发**（Xcode 26.6 已在位，带 iOS 26.5 SDK），只是拿不到 iOS 27 的新能力。Apple 的强制门槛是 **2027 年 4 月**起上传必须用 iOS 27 SDK 构建。

建议：先做完阶段 0–2 的代码工作，**在动 Xcode 版本之前先把 macOS 升级**，不要同时改工具链和业务代码。

## 五、十条铁律

与安卓端同源，**在 iOS 上不得放松任何一条**。

1. **不得编造费率数值。** 找不到就写 `null` 并记录已检索路径。这条优先级最高。
2. **费率四字段强制**：`valid_from` / `valid_to` / `source_doc` / `verified_by`。缺一个，历史测算就无法复现，也无法向审计解释"为什么上个月算出来是另一个数"。
3. **`tier` 分档标注** `gov` / `grid` / `region`，UI 彩色徽标；路径含非 `gov` 段主动告警。**报备价与核定价不得混为一谈。**
4. **网损是乘法项**，不能直接作最短路边权。必须两步：线性近似求候选 → 乘性公式精确重算。
5. **路径唯一标识用节点序列**（`nodes.join(">")`），不能用边的 from/to——对向通行的边存储方向与行进方向相反。
6. **容量制工程按折算的等效度电成本参与比选**，不可按 0 计。
7. **ATC 我国不公开**，宁可标「未获取」也不编系数；容量数据不完整时界面标注「按额定校验、结果偏乐观」。
8. **地图只用白名单底图**（腾讯 / 天地图 / 高德 / 百度），且**代码中不得内嵌任何有效地图密钥**。
9. **`packages/RouteEngine` 不得 import 任何 UI 或网络库。** 它是唯一能脱离界面单独验证的部分，这条纪律破了，算法就再也无法在命令行里回归。
10. **改动算法后必须跑回归**，688 条全过才算完成。改了费率或通道数据则先重新生成基线。

## 六、里程碑

| 里程碑 | 标志 | 对应阶段 |
|---|---|---|
| **M0 · 可跑** | 空白工程在真机冷启动成功 | 阶段 0 |
| **M1 · 可看** | 费率库与拓扑图在手机上翻得动 | 阶段 1 |
| **M2 · 可算** | 688 条基线全过，数值与 Web 一致 | 阶段 2 |
| **M3 · 可改** | 费率能编辑、版本能追溯、地图能降级 | 阶段 3 |
| **M4 · 可用** | 交易员的手机上装上了，且能升级 | 阶段 4 |
| **M5 · 好用** | 原生能力落地，两端长期一致 | 阶段 5 |

**M2 是分水岭。** M0–M1 可以快速推进、允许粗糙；M2 之前的所有工作都是为了让这一步能自动判定成败。

## 七、风险与应对

| 风险 | 应对 |
|---|---|
| 算法移植走样（浮点 / 舍入 / 口径漂移） | 688 条基线把关；金额展示层用 `Decimal`，比对容差固定 `1e-4` |
| 两端费率版本不一致 | `priceVersion` + `dataHash` 强校验，不一致时明确提示而非静默计算 |
| 腾讯地图代理在 App 内不存在，地图一片白 | 内置 SVG 拓扑图兜底（已有测试覆盖）+ 天地图自带 tk；验收项写死"任何环境不得空白" |
| Xcode 27 需要 macOS 26.6，本机 26.4 | 先保留 Xcode 26.6 作基线；升级自成一步，不与业务改动混做 |
| 磁盘可用仅 91 GB | 升级前清理；只装 iOS 27 一个模拟器 runtime，不装全家桶 |
| 组织账号 D-U-N-S 审核 1–4 周 | 与阶段 0 同步启动，不阻塞编码 |
| WebView 壳被审核指南 4.2 拒 | 一期只做内部分发，不走 App Store；若必须上架，先补齐原生能力（离线、原生导航、通知、Face ID、Widget 至少三项） |
| 容量数据不完整（8 条通道无实测值） | 界面显式标注「按额定校验、结果偏乐观」，不静默按额定值算 |
| 西藏基金缺失 | 已显式告警；按 0 计会低估落地成本 |

## 八、明确不做

- **一期不做服务端。** 计算全在端侧，费率库随包发或手动导入。服务端只在出现「多人共用同一份费率库 + 变更留痕 + 行情自动同步」时才引入。⚠️ 一旦接入**自建服务端域名**，App 备案立即从"不需要"变成硬前置。
- **不做第二套独立算法。** 所有实现共用一个契约与一组基线。
- **不使用 Apple Maps 做业务底图。**
- **不在 iOS 上做价格预测。** 属另一专业领域，接现有服务。
