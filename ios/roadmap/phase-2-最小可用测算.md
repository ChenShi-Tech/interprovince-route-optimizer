# 阶段 2 · 最小可用测算

> 周期：2–3 周 ｜ 里程碑：**M2 · 可算** ｜ 前置：阶段 1 完成

---

## 一、核心目标

**iOS 上算出与 Web 版一模一样的落地价。**

这是整个 iOS 端唯一不可让步的目标。界面可以糙、导航可以浅、样式可以后补——但数值必须一致。**M2 之前的所有工作，都是为了让这一步能自动判定成败。**

---

## 二、关键技术点与所需技能

### 2.1 算法移植：五条必须逐条对齐的约定

与 Web 版逐条一致（原文见 `docs/03-数据接口说明.md` 第四节）：

| # | 约定 | 为什么容易做错 |
|---|---|---|
| 1 | **网损是乘法项**，不能直接作最短路边权 | 必须两步：先用线性近似求候选路径，再用乘性公式精确重算。把它当加性边权会系统性低估网损 |
| 2 | **路径唯一标识用节点序列**（`nodes.joined(separator: ">")`） | 不能用边的 from/to——对向通行的边，存储方向与行进方向相反，用边做标识会碰撞 |
| 3 | **段前系数** `1 / Π_{j≥i}(1 − η_j/100)` | 越靠送端的段承担越多电量与损耗。漏掉这层系数，越长的路径错得越离谱 |
| 4 | **落地价含四项省内/通道费用 + 网损折价 + 基金附加** | **送出省输电价格不可漏**——这是最常被漏掉的一项 |
| 5 | **容量制工程用折算的等效度电成本参与比选** | 不可按 0 计；按 0 计会让容量制通道在比选中被系统性高估 |

### 2.2 数值精度策略（本项目最大的隐藏坑）

跨语言复现时，`Double` 会在 `1e-4` 量级出现漂移。必须事先定好策略，不能等回归失败再补：

- **计算层**：保持与 JS 一致的运算顺序。**不要为了"更精确"而重排浮点运算**——重排会改变舍入结果，反而制造分歧。
- **金额展示层**：用 `Decimal` 做四舍五入与格式化，避免"界面上显示的钱加起来不等于总额"。
- **比对容差**：固定 `1e-4`，与安卓侧用同一个值。
- **排查纪律**：两端不一致时，**先怀疑浮点与舍入，再怀疑算法**。按"逐段拆解比对"的方式定位到具体是哪一段开始分歧。

### 2.3 性能与并发

30 节点 / 70 通道的规模下，单次测算在毫秒级。但全量省对扫描（503 个省对）要移出主线程，否则界面会卡。

- `Task.detached` 或 `actor` 承载计算；
- 计算入口设计为**纯函数**：`solve(input, data) -> Result`，无副作用，便于测试；
- Swift 6 严格并发下，出入计算边界的数据结构需要是 `Sendable`（值类型天然满足）。

### 2.4 三口径比选

按《省间电力现货交易规则》3.2.2「优先选输电价格最低的路径」，**默认启用成本劣化阈值（10%）**。运行时必须保留绕行度与跳数上限——否则会算出绕行大半个中国的荒谬路径。

## 三、交付物

1. **iOS 测算 App 主链**：
   - 输入：送端省 / 受端省 / 上网电量
   - 输出：三口径并列的候选方案列表
   - 详情：每一段的输电价、线损、容量占用、费用与核价依据完整拆开
   - 展示：Swift Charts 成本拆解堆叠条；`tier` 彩色徽标（`gov` / `grid` / `region`）
2. **回归测试目标 `RouteEngineRegression`**：读取 `docs/regression-baseline-v2.json`，对 503 个省对 / 1739 条路线逐条比对。

---

## 四、验收标准

| 项 | 判定 |
|---|---|
| **算法回归（唯一门槛）** | 1739 条路线全部在 `1e-4` 容差内通过。比对字段：路径节点序列、落地成本、过网费、送端净收益、送达系数 |
| 版本校验 | `priceVersion` 与 `dataHash` 与 Web 版一致；不一致时提示而非计算 |
| 告警 | 路径含非 `gov` 段的方案主动告警；容量数据不完整的通道标注「按额定校验、结果偏乐观」 |
| 性能 | 单次测算 < 1 s（含渲染）；全量省对扫描不阻塞主线程 |
| 纪律 | 送出省输电价格出现在成本拆解中（可用一条人工用例专项验证） |

> **「跑不过就不算完成。」** 这一条把"移植是否走样"变成了可自动判断的问题，而不是靠人工核对几个案例。

## 五、风险

| 风险 | 应对 |
|---|---|
| 浮点舍入差异导致回归失败 | 保持运算顺序与 JS 一致；金额层用 `Decimal`；容差固定 `1e-4` |
| 漏掉送出省输电价格 | 写成专项用例，而不是靠代码审查 |
| 网损被当作加性边权 | 用现有 Web 版的已知案例做对照，先在小样本上验证 |
| 绕行度 / 跳数上限被漏实现 | 保留默认成本劣化阈值 10%；构造一个"绕行大半个中国"的反例做测试 |
| 容量数据不完整被静默按额定值算 | 界面显式标注，且回归时对这类通道单独记录 |
