# iOS 端

省间电力现货跨省送电路径优选测算工具的 **iOS 客户端**。

> **当前状态（2026-09-15）**：目录与路线图已建立，**工程本体尚未创建**。
> 与 `android/` 一样，本目录先固化结构、契约与纪律，再落代码。

---

## 一、为什么把 iOS 放在这里

`ios/` 与 `android/` 平级，同属 `interprovince-route-app` 这一个 git 仓库。理由有三条：

1. **数据同源。** 端侧要读 `shared/app-data.json`，放在仓库外就得复制一份，必然产生版本漂移。
2. **契约同源。** 算法与字段约定写在 `docs/03-数据接口说明.md`，两端共用一个事实源。
3. **回归同一把尺子。** `docs/regression-baseline-v2.json`（331 个省对 / 693 条路线）是 Web 与安卓共用的验收基线，iOS 也必须对着它跑。

## 四、本机体检结论（2026-09-15 实测）

| 项 | 实测值 | 判定 |
|---|---|---|
| 机型 / 芯片 | Mac Studio，Apple M1 Max | ✅ Apple Silicon，符合 Xcode 27 要求（Xcode 27 已彻底放弃 Intel Mac） |
| 内存 | 32 GB | ✅ 充裕 |
| 系统 | macOS 26.4（25E5218f） | ⚠️ **低于 Xcode 27 要求的 macOS Tahoe 26.6** |
| 已装 Xcode | **Xcode 26.6（17F113）** | ✅ 可用，建议保留为基线工具链 |
| 磁盘可用 | 91 GB（总量 926 GB） | ⚠️ 够用但不宽裕。Xcode 27 安装包 2.85 GB，装上模拟器 runtime 后占用约 30–40 GB |

**由此得出两条硬结论：**

1. **想用 iOS 27 SDK，必须先升 macOS 到 26.6。** 不升级就只能停在 Xcode 26.6——这仍然完全可用（Xcode 26.6 带 iOS 26.5 SDK），只是用不了 iOS 27 的新 API。Apple 的强制门槛在 **2027 年 4 月**：从那时起上传 App Store Connect 必须用 iOS 27 SDK 构建。所以现在不是截止日，但升级不该拖到 2027 年再动。
2. **升级时不要覆盖 Xcode 26.6。** 保留一条能回退的发布链路，Xcode 27 并行安装、独立 DerivedData。

## 五、路线选择：先看一段代码就能明白的约束

`src/app/ui/map.js` 第 147 行有一句注释，它决定了 iOS 壳路线的天花板：

> 判断当前是否运行在带腾讯地图代理的环境里（WorkBuddy 本地预览）。
> 托管到外网后代理不可用，必须改用天地图或内置拓扑图，否则底图会是一片空白。

也就是说，**腾讯地图那条线依赖 WorkBuddy 预览环境注入的本地代理**（`http://127.0.0.1:__WB_HTTP_PORT__/...`）。iOS App 里不存在这个代理。因此 iOS 端能真正用起来的地图只有两种：

- **内置 SVG 拓扑图** —— 完全离线，永远可用，是兜底也是主力；
- **天地图** —— 需要用户自己在应用内粘贴 tk。

这条约束在三条候选路线里都一样成立，不构成选型差异，但**必须写进验收标准**：地图页在任何环境下都不得出现空白。

三条候选路线的完整对比见 [`docs/01-技术选型与路线决策.md`](./docs/01-技术选型与路线决策.md)，结论摘录：

| | A · WKWebView 壳 | B · SwiftUI 原生 | C · React Native |
|---|---|---|---|
| 出包速度 | 1–2 天 | 数周 | 数周 |
| 与 Web 一致性 | 天然一致 | 需回归保证 | 需回归保证 |
| 算法 | 直接复用 JS | 重写为 Swift | 复用 TS 包 |
| 苹果生态能力 | 基本没有 | 最强 | 中等 |
| 走 App Store | ❌ 4.2 高风险 | ✅ | ✅ |

**推荐：A 先行验证，B 作为主力长期路线，C 在「iOS 非战略投入」时才考虑。** 先 A 后 B 不是二选一，A 的成本几乎为零（Web 版已是自包含单文件），能立刻把工具交到交易员手上。

## 七、明确不做

- **不在 iOS 上做第二套算法实现后不管回归。** 任何实现都要对着 693 条基线跑，跑不过不算完成。
- **不使用 Apple Maps 做业务底图。** 地图只用白名单（腾讯 / 天地图 / 高德 / 百度），省界由合规底图负责，自己不画一帧。
- **不在代码里内嵌任何有效地图密钥。**
- **一期不做服务端。** 计算全在端侧，数据随包发或手动导入。
