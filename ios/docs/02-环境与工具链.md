## 二、两条硬结论

### 1. Xcode 27 需要先升 macOS

Xcode 27 要求 **macOS Tahoe 26.6 或更高**。本机 26.4，**想装 Xcode 27 必须先升系统**。

但**不升级也完全能开发**：Xcode 26.6 带 iOS 26.5 SDK，足以支撑阶段 0–3 的全部工作。

Apple 的强制门槛在 **2027 年 4 月**：从那时起，上传 App Store Connect 的 iOS/iPadOS App 必须用 iOS 27 SDK 或更高版本构建。所以现在不是截止日，但升级不该拖到 2027 年再动。

### 2. 升级时不要覆盖 Xcode 26.6

**保留一条能回退的发布链路。** 同时出现"新工具链有 bug"和"旧工具链已删除"是最难收拾的局面。

做法：

```bash
# 并行安装两套 Xcode，各自独立 DerivedData
# 全局仍指向稳定版
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer

# 需要时单次指定，不做全局切换
DEVELOPER_DIR=/Applications/Xcode-27.app/Contents/Developer xcodebuild -version
```

CI 尤其要注意：把 Xcode 的完整 build 号写进日志。同名镜像更新后，光看版本号是无法复现的。

## 三、磁盘规划

Xcode 27 的 dmg 是 **2.85 GB**，安装后带模拟器 runtime 约 **30–40 GB**。可用 91 GB，装得下，但不宽裕。

**只装需要的那一个模拟器 runtime**，不要装全家桶（watchOS / tvOS / visionOS 对本项目无意义）：

```bash
# 查看已装 runtime
xcrun simctl runtime list

# 删除不需要的
xcrun simctl runtime delete <runtime-id>
```

## 四、工具链留档（阶段 0 交付物之一）

装完后把以下命令的**原始输出**存档，这是后续判断"是谁改了什么"的唯一依据：

```bash
sw_vers
xcode-select -p
xcodebuild -version
xcrun --sdk iphoneos --show-sdk-version
swift --version
```

注意 `xcrun --sdk iphoneos --show-sdk-versions` 与实际用于构建的 SDK 可能不同——**以构建日志里的 SDK 为准**。

## 五、签名体系速览

| 组件 | 作用 | 要点 |
|---|---|---|
| **Certificate** | 标识开发者 / 组织身份 | Development 与 Distribution 两类；证书本身有效期 3 年 |
| **App ID / Bundle ID** | 应用唯一标识 | 建议 `com.chenshi.iproute`；与安卓的 `com.iproute.calc` 可不同 |
| **Provisioning Profile** | 证书 + App ID + 设备 UDID 的组合 | Ad Hoc 与 Development 的描述文件列出允许运行的设备；**Ad Hoc 有效期 1 年** |
| **Team** | 账号归属 | 走组织账号时，Team 就是公司主体；这是为什么一开始就要用组织账号 |

### 开发期零成本起步

**普通 Apple ID 也能真机调试**，只是签名 7 天失效、且拿不到推送等能力。

**建议先用免费 Apple ID 把"空白工程上真机"跑通，再决定是否入会。** 这样组织账号 1–4 周的审核期不会阻塞你熟悉环境。

## 六、Xcode 27 中值得用上的能力

| 能力 | 对本项目的价值 |
|---|---|
| 内联代码补全（本地跑在 Neural Engine 上，源码不出机器） | 日常写 SwiftUI 界面，回滚成本低 |
| 智能体编码，支持 `/plan` 先出改动计划再动手 | 重构跨文件时避免"改完 40 个文件才发现方向错了" |
| 支持 MCP 插件 | 可接现有工具链 |
| Device Hub 统一管理模拟器与实体设备 | 阶段 4 真机验证时省事 |
| Xcode Cloud 提速 | 阶段 4 出包链路可考虑 |

⚠️ **不要把"熟悉新功能"和"完成生产迁移"混成一个任务。** 正式版刚发布时，先做小范围验证再谈流水线迁移。
