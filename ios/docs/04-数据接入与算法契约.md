# 数据接入与算法契约

> iOS 端与 Web / 安卓共享的同一份契约。**唯一的事实源是 [`../../docs/03-数据接口说明.md`](../../docs/03-数据接口说明.md)**，本文只写 iOS 侧需要额外注意的部分。

---

## 一、数据来源

| 产物 | 消费方 | 说明 |
|---|---|---|
| `shared/app-data.json` | 安卓 / 服务端 | 独立 JSON，含 schema 版本与价格指纹 |
| `shared/app-data.min.json` | 移动端随包内置 | 紧凑版，体积少约 25% |
| `index.html` | Web | 自包含单文件，数据内联 |

iOS 端默认内置 `app-data.min.json`，并支持从站点同目录或 CDN 拉取更新（与安卓三条通道一致）。

### 版本字段

| 字段 | 作用 |
|---|---|
| `priceVersion` | 费率版本号。**两端不一致会导致同一笔交易算出两个落地价——这比算出错值更难排查** |
| `dataHash` | 完整性校验 |
| `schema` | 结构版本。**新增字段或改结构时必须递增** |

启动即校验。不一致时的正确行为是**明确提示用户**，而不是继续计算。

## 二、必须遵守的算法约定

原文见 [`../../docs/03-数据接口说明.md`](../../docs/03-数据接口说明.md) 第四节。iOS 侧逐条对照：

### 1. 网损是乘法项

**不能直接作为最短路边权。** 必须两步：

1. 用线性近似求候选路径；
2. 用乘性公式精确重算。

把它当加性边权会系统性低估网损。

### 2. 路径唯一标识用节点序列

```
标识 = nodes.joined(separator: ">")
```

**不能用边的 from/to。** 对向通行的边，存储方向与行进方向相反，用边做标识会碰撞。

### 3. 系数体系：段前系数、段后系数、两条链

段前系数（自送端向受端累计）：

```
段前系数_i = 1 / Π_{j≥i}(1 − η_j/100)
```

段后系数（该段出口 / 落地端侧）：

```
段后系数_i = 1 / Π_{j>i}(1 − η_j/100)
```

越靠送端的段承担越多电量与损耗。漏掉这层系数，越长的路径错得越离谱。

**两条系数链——iOS 实现最容易漏的一处**：

| 链 | 用途 | 段线损取值 |
|---|---|---|
| **物理链** | 段入口/出口功率、容量占用、物理损耗电量 | 全部段的核定线损率 |
| **计费链** | 送达系数 D、段前/段后系数、网损电量、计费电量 | `incLoss=true` 的段按 **0** 计 |

依据：S14《省间电力现货交易规则》(2026-04) 3.3.2「输电价格已包含网损的，不再另行收取」。**下文与本文件所有系数凡未注明，均指计费链。** 实现时必须建 `sufT`（计费链）与 `sufP`（物理链）两条后缀积，不得共用。

### 3b. 计量系数：输电费一律按计费链段后电量（⚠️ 防止按送端电量计含线损通道）

**全部段的输电费**：

```
fee_i = t_i × 段后系数_i        （S14 规则 4.3.1）
```

依据链：4.3.1 折算公式 `Σ Pt_m × Π_{r≤m}(1−ρ_r)`，换算到每交付 1 MWh 即「输电价 × 段后系数」；与 3.3.1「专项工程按实际物理计量电量结算」、发改价格规〔2025〕1490 号附件 4 第十八条「按落地端结算电量」一致。

**反例（真实发生过的错法）**：把含线损通道按段前（送端）电量计，单段多收 `1/(1−η)`——灵绍会错成 50.97 而非 48.80 元/MWh。

**iOS 引擎必须内置的专项断言**：

| 用例 | 断言 |
|---|---|
| NX→ZJ 灵绍单段 `segs[0].fee` | `48.80 ± 0.01` |
| SC→JX 雅湖单段 `segs[0].fee` | `68.50 ± 0.01` |

送出省段费 `sendFee`（按段前系数）与区域电网费（见下）不受计量系数影响。

### 4. 落地价构成

完整公式以 [`../../docs/03-数据接口说明.md`](../../docs/03-数据接口说明.md) 第四节为唯一事实源，摘要：

```
省界价 = 出清价 × (1 + g × 网损电量)
       + Σ [ sendFee_i × 段前系数_i ]            送出省段按出口电量（=本段入口电量）
       + Σ [ t_i × 段后系数_i ]                  全部段，见 3b 计量系数
       + 买方区域电量电价 × 1                    一律计一次（S14 3.4.2(a)）
       + Σ [ 过境区域电量电价 × 段后系数_i ]      regional=true 且到达省不在买方区域的联络线段
落地价 = 省界价 × (1 + ρ受/(1−ρ受))              ρ受 = PV[受端].inLoss（上网环节线损）
       + 受端省网输配电价 + 政府性基金及附加
```

⚠️ 三个最常被漏掉的项，**各写专项测试用例，不靠代码审查**：①送出省输电价格 `sendFee`（历史版本曾整项漏掉）；②受端上网环节线损 `inLoss`（2026-09 新增字段）；③过境区域联络线段费用。

### 5. 容量制工程

用**折算的等效度电成本**参与比选，**不可按 0 计**。按 0 计会让容量制通道在比选中被系统性高估。

## 三、iOS 侧特有的注意点

### 3.1 数值精度

跨语言复现时 `Double` 会在 `1e-4` 量级漂移。策略必须事先定好：

| 层 | 做法 |
|---|---|
| 计算层 | **保持与 JS 一致的运算顺序。** 不要为了"更精确"而重排浮点运算——重排会改变舍入结果，反而制造分歧 |
| 金额展示层 | 用 `Decimal` 做舍入与格式化，避免"界面上的钱加起来不等于总额" |
| 比对容差 | 固定 `1e-4`，与安卓侧同一个值 |

**排查纪律：两端不一致时，先怀疑浮点与舍入，再怀疑算法。** 定位方式是从送端开始逐段拆解比对，找到第一个分歧点。

### 3.2 数据模型

```swift
// ✅ 显式 CodingKeys + 非可选关键字段 + 自定义 init(from:) 抛错
// ❌ 禁止 decoder.keyDecodingStrategy = .convertFromSnakeCase
```

理由见 [`03-工程结构与模块划分.md`](./03-工程结构与模块划分.md) 第四节。

**费率缺失必须表达为 `nil` 并记录已检索路径，不得编造数值。**

### 3.3 `tier` 分档

字段 `tier` 取值 `gov` / `grid` / `region`：

- UI 用**彩色徽标**显示；
- 路径含非 `gov` 段时**主动告警**；
- **不得把报备价与核定价混为一谈。**

发改委核定价可获得率约 **60%**：2018–2019 存量工程、2021–2023 新投运直流可拿到；**2024 年后新投运（金永、中衡、坤渝、庆东、宝合）与吉泉、昭沂只有国网报备价。**

### 3.4 容量与 ATC

- **额定容量 ≠ 可用输电能力（ATC）。** 天中 8000 额定 / 5400 实际，昭沂 10000 / 5300（4500 为 2018 年旧值，改进计划已订正）。
- ATC 的 TRM / CBM 取值我国不公开，**工具中不得写死默认值**。
- 实际输送能力缺失的通道（当前 25/64 条，含无核定容量的联络线），界面标注「按额定校验、结果偏乐观」。
- **断面限额是「向注册市场成员披露」的信息，不是公众信息**，公开渠道只能拿到报道 / 文献值。

### 3.5 绕行度与跳数上限

**必须保留**，否则会算出绕行大半个中国的荒谬路径。另按《省间电力现货交易规则》3.2.2「优先选输电价格最低的路径」，**默认启用成本劣化阈值（10%）**。

## 四、回归验收

### 基线

`docs/regression-baseline-v2.json` —— **503 个省对、693 条路线**，含费率快照 sha256。（⚠️ 2026-09-16 随通道方向与计费口径重构重建：专项工程单向通行 + 全段按段后电量计费；旧「1739 条」为双向枚举旧口径，已作废，不得作为 iOS 回归目标。）

### 比对字段与容差

| 字段 | 容差 |
|---|---|
| 路径节点序列 | **必须完全一致**（字符串枚举，无容差） |
| 落地成本 | `1e-4` |
| 过网费 | `1e-4` |
| 送端净收益 | `1e-4` |
| 送达系数 | `1e-4` |

### 判定

> **693 条全过才算完成。跑不过就不算完成。**

Web 版用 `node tools/baseline-check.mjs` 校验；iOS 侧在 `RouteEngineRegression` 测试目标里跑同一组用例。

**注意**：路径节点序列必须完全一致——这不只是数值问题，容差放过它会让"走的完全不是同一条路但钱差不多"这种情况溜过去。

### 改了数据怎么办

改了费率或通道数据，需先重新生成基线（`node tools/baseline2.mjs`），再跑两端比对。**基线是与费率快照绑定的，不能跨费率版本混用。**
