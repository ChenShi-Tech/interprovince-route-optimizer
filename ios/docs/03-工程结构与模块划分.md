# 工程结构与模块划分

> iOS 工程的目录约定、模块职责与依赖方向。**依赖方向是这个文档存在的唯一理由。**

---

## 一、目录结构

```
ios/
├── app/                          Xcode 工程本体
│   ├── InterprovinceRoute.xcodeproj
│   ├── InterprovinceRoute/       应用源码
│   │   ├── App/                  入口、路由、依赖装配
│   │   ├── Features/             按功能分模块，一个功能一个文件夹
│   │   │   ├── Calc/             测算页：参数输入、方案列表、方案详情
│   │   │   ├── TariffLibrary/    费率库：浏览、编辑、版本对比
│   │   │   ├── Map/              网架图：内置拓扑图 / 天地图（WKWebView）
│   │   │   └── DataAdmin/        数据管理：导入导出、版本信息
│   │   ├── Models/               Codable 数据模型（与 app-data.json 对齐）
│   │   ├── Storage/              SwiftData 模型与持久化
│   │   └── Resources/            app-data.min.json、图标、LaunchScreen
│   └── InterprovinceRouteTests/  单元测试（Swift Testing）
├── packages/RouteEngine/         算法包：Swift Package，纯逻辑
├── tests/                        回归用例与基线对照
├── tools/                        出包、基线对照、图标生成脚本
├── roadmap/                      分阶段路线图
└── docs/                         本目录
```

**命名对齐**：功能模块名与 `android/` 及 Web 版保持一致（测算 / 费率库 / 网架图 / 数据管理），这样三端讨论同一个功能时不会各叫各的。

---

## 二、模块职责

| 模块 | 职责 | 不该做的事 |
|---|---|---|
| `App/` | 入口、导航装配、全局状态注入 | 不写业务逻辑 |
| `Features/Calc/` | 参数输入、结果展示、成本拆解 | **不自己实现路径枚举与计价** |
| `Features/TariffLibrary/` | 费率浏览、编辑、版本对比、校验提示 | 不直接读文件，走 `Storage/` |
| `Features/Map/` | 拓扑图渲染、WKWebView 与原生通信、降级逻辑 | 不内嵌任何有效地图密钥 |
| `Features/DataAdmin/` | 导入导出、schema 校验、版本信息展示 | 校验规则来自 `RouteEngine` 的模型定义，不重复实现 |
| `Models/` | 与 `app-data.json` 一一对应的 `Codable` 结构 | 不放业务方法 |
| `Storage/` | SwiftData 模型、迁移、留痕写入 | 不做数值计算 |
| **`packages/RouteEngine/`** | 图构建、邻接表、路径枚举、乘性网损精算、三口径比选 | **不得 import SwiftUI / UIKit / 网络库** |

## 三、依赖方向（硬约束）

```
        App ──────────────┐
         │                │
         ▼                ▼
   Features/*          Storage
         │                │
         └───────┬────────┘
                 ▼
              Models
                 │
                 ▼
           RouteEngine          ← 只能向下依赖，绝不向上
```

规则：

1. **`RouteEngine` 是最底层，不依赖任何上层。** 尤其**不得 import SwiftUI / UIKit**，也不得发起网络请求。
2. `Features/*` 之间不互相依赖；需要共享的东西下沉到 `Models/` 或 `RouteEngine`。
3. `Storage/` 不做计算，`RouteEngine` 不碰持久化。**两者唯一的交界是数据模型。**

### 为什么第 1 条不可让步

`RouteEngine` 是**唯一能脱离界面单独验证**的部分。它能在命令行里 `swift test` 跑 1739 条回归，能在 CI 里跑，能在两端比对输出。

这条纪律一旦破了——哪怕只是"顺手 import 一下 UIKit 好读个颜色"——**算法就再也无法脱离 UI 单独回归了**。这跟安卓侧 `docs/01-安卓开发框架.md` 写的是同一条硬约束。

**执行方式**：在 `Package.swift` 里刻意不声明任何 UI 依赖，让编译器替你守这条线。

## 四、数据模型纪律

对齐 `shared/app-data.json` 时：

```swift
// ✅ 正确：显式 CodingKeys，缺字段即报错
struct Channel: Decodable {
    let id: String
    let from: String
    let to: String
    let price: Decimal?      // 无核定价时显式 nil，不编造
    let tier: Tier           // gov / grid / region

    enum CodingKeys: String, CodingKey {
        case id, from, to, price, tier
    }
}
```

```swift
// ❌ 禁止：自动转换会掩盖字段缺失
decoder.keyDecodingStrategy = .convertFromSnakeCase
```

**理由**：自动转换下，漏掉一个字段会静默变成 `nil` 或抛出一个不含上下文的错误。而"某条通道的费率悄悄消失了"在数值上的表现是**算得偏小**——看起来完全正常，极难定位。

**原则：宁可启动失败，也不要算出一个看起来正常的错值。**

## 五、版本与留痕

| 内容 | 存放位置 |
|---|---|
| 内嵌数据 | `app/InterprovinceRoute/Resources/app-data.min.json` |
| 费率库运行时状态 | SwiftData |
| 计算留痕（输入 + `priceVersion` + 引擎版本） | SwiftData，只增不改 |
| 引擎版本号 | `RouteEngine` 内的常量，代码变更即递增 |

启动时必须校验 `priceVersion` 与 `dataHash`，**不一致时明确提示，绝不静默计算**。
