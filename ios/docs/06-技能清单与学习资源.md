# 技能清单与学习资源

> 按阶段列出"要会什么"，并给出官方文档入口。**优先看 Apple 官方文档**——第三方教程的版本滞后是常态，iOS 每年一个大版本。

---

## 一、起点判断

团队是前端（TypeScript / React）背景，这决定了学习路径：**不要从"什么是变量"开始**，直接做映射。

| 你已经会的 | Swift 里对应什么 | 学习成本 |
|---|---|---|
| TS 类型系统 | Swift 强类型 + 可选类型 | 低 |
| 对象字面量 | `struct`（值语义） | 低 |
| 联合类型 | `enum`（带关联值） | 低 |
| `JSON.parse` | `Codable`（编译期生成） | 低 |
| `Promise` / `async` | `async` / `await` | **最低** |
| `interface` | `protocol` | 低 |
| React 组件状态 | `@State` / `@Observable` | 中（心智略不同） |
| — | **Swift 6 严格并发（`actor` / `Sendable`）** | **最高** |

**唯一的真实门槛是并发模型，不是语法。** 建议在阶段 2 真正用到时再深入，不要在阶段 1 提前啃。

## 三、三条学习纪律

1. **以官方文档为准。** iOS 每年一个大版本，第三方教程滞后一年是常态。遇到 API 对不上，先查官方文档的可用性标注。

2. **不要先学完再动手。** 本路线的设计是「学一点、做一个交付物」——阶段 1 的两个小程序（费率库浏览器、拓扑图）本身就是最好的练习，而且产出的是项目真正需要的东西。

3. **优先看 Apple 官方示例工程。** Xcode 里可以直接打开官方教程的示例项目，比读文档快。

## 四、容易踩的认知偏差

| 偏差 | 实际情况 |
|---|---|
| 「Swift 和 TS 差不多，一周就够」 | 语法确实快，但**并发模型和值语义**需要时间建立直觉 |
| 「SwiftUI 就是 React」 | 状态管理有相似之处，但 SwiftUI 是**声明式 + 数据流驱动**，且 `@State` 的生命周期与 React 的 state 不同 |
| 「iOS 出包和安卓一样简单」 | **完全不同。** iOS 必须过签名与分发渠道，没有"出个文件直接装"的路径 |
| 「先学完整套 Swift 再做项目」 | 会导致大量学习投入浪费在本项目用不到的特性上 |
| 「浮点误差可以用容差糊过去」 | 容差只适用于数值字段；**路径序列必须完全一致**，容差放过它会让"走的不是同一条路但钱差不多"溜过去 |
